# Contributing

Start with a small, reproducible problem. Open a sanitized issue or a focused pull request explaining the observed behavior, desired behavior and validation.

## Local checks

Use Python 3.11+ on Linux, macOS or WSL, with Git available:

```bash
python3 -B tools/check.py
```

The suite uses local temporary repositories and fictional inputs. It does not require a GitHub token or prove hosted recovery. Keep test fixtures deterministic and avoid live account dependencies.

## Scope

Preserve request identities, immutable original prompts, revision checks and explicit authorization boundaries. Keep ticket criteria, worker completion and independent acceptance separate. A fallback must not silently turn an unknown observation into success.

For instruction changes, keep the main workflow short and put substantial conditional material behind references. Update the English and French getting-started text when user-facing behavior changes.

For tracker layout changes, generate the demo, open it in a browser and check light/dark appearance, narrow screens, search, filters, dependency anchors and prompt copying. The HTML must remain self-contained and work without network access. Inspect the rendering as well as running the structural checks.

## Public data

Use fictional tickets and temporary paths in examples. Keep credentials, private repository names, personal workstream state, reports and operational checkpoints out of commits and issues. The skill's public repository is a distribution package, not an operational coordination remote.
